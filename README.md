# План локального рекрутинга (ПЛР) — веб-калькулятор

Веб-версия Excel-таблицы планирования персонала ресторана. Вы вносите прогнозные
показатели (товарооборот, транзакции, цели по производительности), а сайт по
формулам исходной таблицы рассчитывает **потребность в персонале** и **сколько
сотрудников необходимо принять** с учётом текучести, отпусков и времени обучения.

Открыть локально: откройте `index.html` в браузере (или отдайте папку любым
статическим сервером / GitHub Pages). Сборка не требуется — чистый HTML/CSS/JS.

**Онлайн (GitHub Pages):** https://ilyamerk.github.io/local_recruting/

Как включить (разовая настройка, делается один раз владельцем репозитория):
Settings → Pages → Build and deployment → Source: **Deploy from a branch** →
Branch: **main**, папка **/(root)** → Save. Через 1–2 минуты сайт станет доступен
по адресу выше; при каждом пуше в `main` он обновляется автоматически.
Файл `.nojekyll` отключает обработку Jekyll — статика отдаётся как есть.

## Что делала исходная Excel-таблица

Файл содержал 6 листов:

| Лист | Назначение |
|------|-----------|
| **Инструкция** | Порядок заполнения (14 шагов). |
| **ПЛР Ресторан 1 / 2** | Основной расчёт потребности в наборе на 12 месяцев + учёт источников набора (факт: затраты / принято / обращений, стоимость найма, конверсия). |
| **Текучесть и отпуска Ресторан 1 / 2** | Разбивка персонала по ставкам (0,5 / 1 / 1,5) для действующих сотрудников, плановой текучести и отпусков/больничных. |
| **ПЛР Территория** | Сводный ПЛР = поэлементная сумма показателей ресторанов. |

> В исходном файле листы **ПЛР Ресторан 2**, **Текучесть и отпуска Ресторан 2** и
> **ПЛР Территория** были **скрыты** (в Excel видно только 3 вкладки из 6).
> Чтобы показать их в Excel: правый клик по вкладке листа → «Показать…» (Unhide).

Ключевые понятия:
- **SPMH** (Sales Per Man Hour) — цель по производительности, выручка на 1 чел·час.
- **TCPH** (Transactions Count Per Hour) — цель по продуктивности, транзакций на 1 чел·час.
- **Ставка** — режим занятости сотрудника: `0,5` (< 100 ч/мес), `1` (100–170 ч/мес), `1,5` (> 170 ч/мес).
- **FTE / ИТОГО** — приведённое число ставок = Σ(количество × вес ставки).

### Формулы расчёта (перенесены без изменений)

Для каждого месяца:

```
TCPH (если не задан вручную)      = транзакции ÷ SPMH        (Excel R6)
Необходимо часов (SPMH)           = т/о ÷ SPMH               (R11 = R4/R5)
Необходимо часов (TCPH)           = транзакции ÷ TCPH        (R12 = R7/R6)
Сотрудников по SPMH               = часы SPMH ÷ ср. загрузка (R13 = R11/R16)
Сотрудников по TCPH               = часы TCPH ÷ ср. загрузка (R14 = R12/R16)
Действующих сотрудников           = всего часов ÷ ср. загрузка (R17 = R15/R16)

ПОТРЕБНОСТЬ (чел)                                            (R18)
  = (Сотр.SPMH + Сотр.TCPH) / 2
    − Действующие
    + Отпуска + Текучесть + Кадровый резерв

НЕОБХОДИМО ПРИНЯТЬ (обучение ~20 дней)                       (R19)
  = потребность следующего месяца (опережающий набор),
    январь = потребность(январь) + потребность(февраль),
    декабрь = план по данным января следующего года.
```

Текучесть/отпуска (лист «Текучесть»):

```
ИТОГО (FTE) = кол-во(0,5)×0,5 + кол-во(1)×1 + кол-во(1,5)×1,5
```

Территория:

```
Любой показатель(территория) = Σ показатель(ресторан_i)
```

Источники набора (факт):

```
Стоимость 1 принятого   = Σ затраты ÷ Σ принято
Стоимость 1 обращения   = Σ затраты ÷ Σ обращений
Конверсия               = Σ принято ÷ Σ обращений × 100%
```

> Примечание. В исходной таблице ячейка TCPH (R6) содержала формулу
> `= транзакции ÷ SPMH`, из-за чего часы по TCPH вырождались в SPMH.
> Инструкция при этом требовала вносить TCPH как самостоятельную цель.
> В калькуляторе поле TCPH сделано **вводимым**: если оставить его пустым —
> подставляется исходное авто-значение `транзакции ÷ SPMH`; если ввести своё —
> используется оно (тогда «часы по TCPH» считаются корректно).
> Раздел учёта источников в оригинале содержал «битые» ссылки (`#REF!`) —
> здесь он реализован заново с корректными агрегатами.

## Как пользоваться

1. Откройте вкладку своего ресторана.
2. **Планирование (ПЛР)** — внесите прогноз т/о и транзакций, цели SPMH/TCPH,
   кадровый резерв, всего отработанных часов и среднюю загрузку.
3. **Текучесть и отпуска** — распределите сотрудников по ставкам; ИТОГО (FTE)
   планового увольнения и отпусков автоматически попадает в расчёт ПЛР.
4. **Источники набора** — учёт факта по каналам набора и метрик найма.
5. **∑ Территория** — автоматическая сводка по всем ресторанам.

Цвета ячеек (как в оригинале): без заливки — **ввод**, жёлтые — **авторасчёт**,
голубые — **итоговый результат**. Отрицательная потребность (зелёным) означает
избыток персонала — набор не требуется.

Кнопки в шапке:
- **Excel** — скачать результат в Excel-файл (многолистовой: по листу на каждый
  ресторан + «Территория», с той же цветовой кодировкой). Формат SpreadsheetML
  (`.xls`), открывается в Excel, LibreOffice и Google Таблицах.
- **Экспорт/Импорт** — сохранить/загрузить все введённые данные в JSON-файл.
- **Печать** (в т.ч. PDF), **Сброс**. Можно добавлять и переименовывать рестораны.

Данные хранятся локально в браузере (localStorage) и никуда не отправляются.

## Структура проекта

```
index.html               — разметка и подключение скриптов
assets/styles.css         — оформление (светлая/тёмная тема, печать)

```
